# Haunter: build brief

Build a Windows 64-bit **VST3 audio effect** (not an instrument) for Cubase called **Haunter**. The user loads a sample (typically a kick or any one-shot), and the sample's volume shape ducks the incoming track, like a ghost-kick sidechain. The sample can also be blended into the output.

Follow the same Rust approach as `..\Sparkletop\plugin` (look at its Cargo.toml, .cargo config, static CRT, and VST3 bundle layout) and the knob look of the Dropout plugin (`..\Sparkletop` commit 56acf79 copied Dropout's disc, track, and blue arc knobs; reuse that style). Since 1.6.1 the accent is #7C6EBB instead of blue, everywhere: knob arcs, lit toggles, the waveform region, the meter, menu selections, the text cursor, and the Dream Eater fill, with the light and grey tints derived from it.

## Behaviour
- **Trigger:** synced to Cubase's tempo and transport. Rate choices are 1/1, 1/2, 1/4, 1/8, 1/16, plus dotted and triplet variants. Retrigger on the grid only while the transport plays.
- **Sample region:** Start and End times within the sample. Show the waveform in the UI with draggable start and end handles.
- **Restart** toggle, on by default. On: the region plays once from Start on every Rate grid step (from End with Backward; with Levitate, alternately forward from Start and backward from End, since 1.7.7). Off: the region loops continuously while the transport plays, and the Rate knob keeps its normal look but ignores dragging, scrolling, and double-clicks, with its readout replaced by a grey ∞ (U+221E, from the font if it has the glyph, drawn otherwise). Turning Restart back on shows the fraction again. Old states map One-shot to Restart on and Loop to Restart off.
- **Direction** menu (since 1.7, replacing the Reverse toggle), styled like the preset menu (both centre their text, on the button and in the list, since 1.7.2): **Forward** (the default) plays the region from Start to End; **Backward** plays it from End to Start; **Levitate** ping-pongs between Start and End continuously. Choosing Forward or Backward mid-playback turns the playhead round at once from its current position (within the next block), with a 1 ms crossfade between the old and new directions whose gains add up to one, so there is no click. Levitate turns round at each marker by reflecting: the frame at the marker plays twice and the next ones mirror the last ones, so there is no jump and no fade. With Restart on (since 1.7.7; before, each step restarted it from Start going forward, like Forward), Levitate alternates per Rate step: one step plays forward from Start, the next backward from End, and so on, each retriggered with the same crossfade as Forward and Backward, one pass per step, stopping at the far handle without bouncing. The alternation is set by the parity of the grid step's index counted from the song's start (beat 0 is step 0, forward), taken from the host's song position, so it is the same across loops and wherever playback starts (starting on an odd step starts backward). Restart only triggers with a song position, so no fallback counter is needed. With Restart off it bounces for as long as the transport plays. Switching to Levitate keeps the current direction. When the transport stops, the current pass finishes and stops. The ducking envelope, Dream Eater's swell, the blended sample, and the waveform playhead follow the direction actually playing. It is an automatable enum parameter with the new ID `direction` (the old toggle was `reverse`): old states map Reverse on to Backward and off to Forward, and user preset files and the selected preset saved in a project map the same way (so no false `*`); factory presets set Forward. Old automation of Reverse does not carry over to the new ID. Choosing from the menu holds the edit open (begin, then the value every frame) until the parameter has it or about a second passes, the same as the toggles since 1.2.1, because Cubase does not apply an edit that opens and closes at once; the menu shows the choice meanwhile.
- **Ducking:** an envelope follower runs on the sample's playback (after the HP and LP filters). Its shape sets gain reduction on the input. Controls are Depth (0 to 100%, how much the track ducks at the unfiltered sample's peak), and Attack and Release smoothing for the follower.
- **Filters:** HP and LP cutoffs filter the sample itself, so they change both the sample heard through Sample Blend and the ducking. Filtering away part of the sample makes the duck shallower.
- **Sample output:** Sample Volume (default 0.0 dB), plus Sample Blend (how much of the sample is mixed into the output, default 0, so it's only a ghost).
- **Mix:** dry/wet for the ducking effect. There is no output gain: the output is always at unity. Old states that saved Output still load, and the value is ignored.
- **Dream Eater:** a knob in Output's old place in the layout (the last knob of the lower row). It is glassy, sparkly, bell-like ear candy in the track's key, in the manner of Botanica or Petalcore. It must never sound metallic, swoopy, or like reversed vinyl, and it has no pitch sweep.
  - **Key detection:** the track's key is detected from its audio, cheaply and without allocating on the audio thread. Haunter builds a pitch-class profile from an FFT of a decimated buffer over a few seconds and correlates it with Krumhansl-style key profiles. The detection is smoothed heavily: the last confident key is held, a new key is only taken once it has been clearly confident for about 1.5 s, and noise and silence change nothing. C is used until a key is confident.
  - **The chord:** resonators tuned to the key's major pentatonic (a minor key uses its relative major's) play the root, fifth, and ninth, with octave partials at half level, and since 1.7.5 the ninth also two octaves up at a quarter level for sparkle at about 2 to 3.7 kHz, between roughly 200 Hz and 3.7 kHz. The sparkle must stay sparkly, never shrill: on white noise it sits a few dB under the ninth and at least 10 dB over everything above 4.2 kHz. They are spread in stereo but fed from the mid, so the chord is mono-compatible. They are excited only by the track itself: a copy of it taken before the duck and delayed by the Attack time plus 120 ms (four of the swell's 30 ms bloom times, about when the bloom peaks, since 1.7.5; 1.7.4 used plus 50 ms), so its energy arrives in the gap right after each duck, still gated by the hit (about 10% open between hits, fully open on each). There is no noise generator or other added source anywhere in Dream Eater, and no saturation or distortion of the excitation, so silence in is silence out. Each note is a left and right pair drifting up to 9 cents against each other (5 before 1.7.5), slowly (0.08 to 0.14 Hz) so it never sounds chorusy, for a stereo shimmer, with the fifth and ninth panned 75% and their octaves 50% the other way. Summed to mono the chord must lose no level. Since 1.6.3 one side of each pair hears the track about 6 ms later, rounded to whole cycles of its note plus a quarter cycle, so the sides ring a quarter-cycle apart: wide, with nothing cancelling in mono, and still no added source.
  - **Playing it:** the sample's envelope, after Direction, HP, and LP and following the same playback as the ducking, swells the chord in on each hit, and the chord rings out softly after. Since 1.7.5 the swell is a soft 60 to 120 ms bloom (10-90% rise) that peaks just after the duck, about 120 ms after the hit, instead of a 25 ms rise hidden inside it; the 10% floor between hits stays. The chord is added after the duck, so it blooms in the space each hit opens. Turning the knob clockwise makes it louder and lengthens the tail, from 0.3 s to 0.9 s.
  - **Tone and safety:** the wet is high-passed at 180 Hz and gently lifted above 1.5 kHz, and the resonators are damped so it is never shrill. A key change crossfades to a second set of resonators while the old chord rings out, so retuning never clicks.
  - **Strength and level:** fully counter-clockwise is Off, a bit-exact bypass, and the readout says "Off". The default is Off, and states without it load with it Off. 100% is clearly audible, changing the test track at least as much as the 1.4.1 comb did (an RMS difference from Off above 0.3, measured through the real VST3 wrapper with Water loaded, since 1.6.0 passed its unit tests yet was inaudible in Cubase). It must also be clearly audible on real material, in any key and timbre, including off-key, noisy, and drum material and sustained legato strings: 1.6.2 was inaudible in Cubase on a legato cello because its few-hertz-wide resonators keep 25 to 45 dB less power than a real track and the leveller could only turn them up by 18 dB. Since 1.6.3 the leveller can turn the chord up by 60 dB (it turns it down at once and up by at most 60 dB a second, so nothing bursts out when the track starts), the chord is kept under the track's own recent peak. Since 1.7 the chord sits about 4 dB under the ducked track at 100% (1.6.3: about 7 dB) with the track turned down about 2.4 dB (1.6.3: about 1 dB), and the makeup aims 0.3 dB under the ducked track at 100% so tracks with gaps between hits don't come out louder; the existing limiter still keeps peaks under the track's own peak and 0 dBFS, with no saturation or noise. Host tests on the factory Paper, Stone, and Wind WAVs and two synthesized legato cellos require a difference from Off between 6 and 2 dB under the track (spectrum louder than 8 dB under), the chord's notes up by more than 4 dB, and loudness within 1.25 dB. Loudness stays matched to Off (the output is brought back to the ducked track's loudness when the chord lines up with the track or finds little to ring), peaks stay at or below about 1.02, there is no DC, and the resonators are stable.
- **Dream Eater key override:** right-clicking the Dream Eater knob opens a context menu with Auto (the default) and the 12 keys, each shown by its root only (C, C#, D, D#, E, F, F#, G, G#, A, A#, B; since 1.7.4). Nothing on the panel shows the choice, not even a label. The choice is kept in the plugin state and in user presets, under `dream-key`. Old projects and presets load on Auto, and factory presets and `--` set Auto. Right-clicking never changes the knob's value, and left-drag and double-click work as before.
- **Dream Eater look:** drawn like the knob in Dropout's Destroy section (The End, in `C:\Users\antho\Dropout`): same size and label style as the other knobs, with a dark grey disc, dark outline and track, a white value arc, a thicker white pointer, and an accent-coloured fill along the white arc showing the live amount. The other knobs keep their look.
- **Gain-reduction meter** in the UI.
- **Loading:** drag-and-drop a WAV, AIFF, or MP3 onto the plugin window, or click inside the waveform rectangle to open the file browser. There is no Load button. With no sample, the rectangle reads exactly "Drop a sample here" and a click anywhere in it opens the browser. With a sample, only a plain click (not a drag, not on the Start or End handle) opens it. The pointer becomes a hand where a click opens the browser. Nothing sits under the title while no sample is loaded; once one is, its name and length show there. MP3s are decoded in pure Rust (Symphonia, `mp3` feature only), with the encoder delay trimmed when the file says how long it is, and stored in the state as decoded audio like any other format. Resample to the host rate.
- **State:** the sample audio itself is embedded in the plugin state, so a Cubase project or preset reopens with the sample even if the original file moved.
- **Presets:** a preset dropdown left of a **Save** button, at the right of the title. **--** (called Init in 1.4) means no sample and default settings, is first in the menu, and is where a new instance starts. It is stored as `{"kind":"none"}`, so projects from any version reopen on it, and neither `--` nor `Init` can be used as a user preset name. The factory presets, in this order after `--`, are **Daisy**, **Paper**, **Press**, **Spin**, **Stone**, **Umber**, **Water**, and **Wind**. Each loads `presets\<Name>.wav`, embedded in the plugin binary with `include_bytes!`, with the default settings, and the sample is named after the preset. Daisy replaced Gaze in 1.7.6; a project saved on Gaze must still reopen with its sample (kept in the state) and show Gaze, without panicking, though Gaze is no longer in the menu and its name is free for user presets. Save asks for a name inline (a text field with OK and Cancel, no native dialog) and stores the sample's audio and every parameter value in `%APPDATA%\Haunter\Presets`, one JSON file per preset. Saved presets are listed after the factory ones and persist across sessions. Saving under an existing name overwrites it.
- **Modified indicator:** when any parameter, Start or End, Restart or Direction, or the sample differs from the selected preset, the name shows a trailing `*` (`Water*`). Choosing the preset again or saving clears it. The selected preset and what it set are saved in the plugin state, so a Cubase project reopens showing the same name and modified state.
- **Latency:** none needed (no lookahead).

## Deliverables
1. Source in this repo, with DSP unit tests (envelope follower, tempo-grid trigger timing, Restart on vs off, Backward, Direction switching mid-pass and Levitate ping-pong without clicks, legacy Reverse mapping, Direction's normalized values round-tripping through the VST3 wrapper, a Direction choice reaching a host that only takes edits held open across process calls, HP and LP changing the output, start/end, Dream Eater Off being a bypass, Dream Eater changing the output more as it turns up and staying stable at max with peaks at or below 1.02, key detection on synthetic A minor and D major sequences, a smooth retune, the key override kept in the state and presets, state save/restore with the embedded sample, loading old states, decoding a small MP3 fixture, Rate locked with the ∞ readout while Restart is off, the menu order and every factory preset loading its embedded sample, a user preset saved to a temporary folder and read back with its sample and parameters intact, and the `*` appearing after a change and clearing after saving or choosing the preset again).
2. `cargo build --release` produces the DLL. Package it as `release\Haunter.vst3\Contents\x86_64-win\Haunter.vst3` with the proper bundle layout.
3. README with the controls and the install steps.
4. Commit when it builds and the tests pass.
