# Haunter: build brief

Build a Windows 64-bit **VST3 audio effect** (not an instrument) for Cubase called **Haunter**. The user loads a sample (typically a kick or any one-shot), and the sample's volume shape ducks the incoming track, like a ghost-kick sidechain. The sample can also be blended into the output.

Follow the same Rust approach as `..\Sparkletop\plugin` (look at its Cargo.toml, .cargo config, static CRT, and VST3 bundle layout) and the knob look of the Dropout plugin (`..\Sparkletop` commit 56acf79 copied Dropout's disc, track, and blue arc knobs; reuse that style). Since 1.6.1 the accent is #7C6EBB instead of blue, everywhere: knob arcs, lit toggles, the waveform region, the meter, menu selections, the text cursor, and the Dream Eater fill, with the light and grey tints derived from it.

## Behaviour
- **Trigger:** synced to Cubase's tempo and transport. Rate choices are 1/1, 1/2, 1/4, 1/8, 1/16, plus dotted and triplet variants. Retrigger on the grid only while the transport plays.
- **Sample region:** Start and End times within the sample. Show the waveform in the UI with draggable start and end handles.
- **Restart** toggle, on by default. On: the region plays once from Start on every Rate grid step. Off: the region loops continuously while the transport plays, and the Rate knob keeps its normal look but ignores dragging, scrolling, and double-clicks, with its readout replaced by a grey ∞ (U+221E, from the font if it has the glyph, drawn otherwise). Turning Restart back on shows the fraction again. Old states map One-shot to Restart on and Loop to Restart off.
- **Reverse** toggle: plays the region backwards, from End to Start. The ducking follows the reversed shape.
- **Ducking:** an envelope follower runs on the sample's playback (after the HP and LP filters). Its shape sets gain reduction on the input. Controls are Depth (0 to 100%, how much the track ducks at the unfiltered sample's peak), and Attack and Release smoothing for the follower.
- **Filters:** HP and LP cutoffs filter the sample itself, so they change both the sample heard through Sample Blend and the ducking. Filtering away part of the sample makes the duck shallower.
- **Sample output:** Sample Volume (default 0.0 dB), plus Sample Blend (how much of the sample is mixed into the output, default 0, so it's only a ghost).
- **Mix:** dry/wet for the ducking effect. There is no output gain: the output is always at unity. Old states that saved Output still load, and the value is ignored.
- **Dream Eater:** a knob in Output's old place in the layout (the last knob of the lower row). It is glassy, sparkly, bell-like ear candy in the track's key, in the manner of Botanica or Petalcore. It must never sound metallic, swoopy, or like reversed vinyl, and it has no pitch sweep.
  - **Key detection:** the track's key is detected from its audio, cheaply and without allocating on the audio thread. Haunter builds a pitch-class profile from an FFT of a decimated buffer over a few seconds and correlates it with Krumhansl-style key profiles. The detection is smoothed heavily: the last confident key is held, a new key is only taken once it has been clearly confident for about 1.5 s, and noise and silence change nothing. C is used until a key is confident.
  - **The chord:** resonators tuned to the key's major pentatonic (a minor key uses its relative major's) play the root, fifth, and ninth, with softer octave partials, between roughly 200 Hz and 2 kHz. They are spread in stereo but fed from the mid, so the chord is mono-compatible. Besides the track, they hear soft noise that follows the track's level, so every chord note sounds even where the track has nothing at its pitch. Each note is a left and right pair drifting a few cents against each other, for a stereo shimmer.
  - **Playing it:** the sample's envelope, after Reverse, HP, and LP and following the same playback as the ducking, swells the chord in on each hit, and the chord rings out softly after. The chord is added after the duck, so it blooms in the space each hit opens. Turning the knob clockwise makes it louder and lengthens the tail, from 0.3 s to 0.9 s.
  - **Tone and safety:** the wet is high-passed at 180 Hz and gently lifted above 1.5 kHz, and the resonators are damped so it is never shrill. A key change crossfades to a second set of resonators while the old chord rings out, so retuning never clicks.
  - **Strength and level:** fully counter-clockwise is Off, a bit-exact bypass, and the readout says "Off". The default is Off, and states without it load with it Off. 100% is clearly audible, changing the test track at least as much as the 1.4.1 comb did (an RMS difference from Off above 0.3, measured through the real VST3 wrapper with Water loaded, since 1.6.0 passed its unit tests yet was inaudible in Cubase). Loudness stays matched to Off, peaks stay at or below about 1.02, there is no DC, and the resonators are stable.
- **Dream Eater key override:** right-clicking the Dream Eater knob opens a context menu with Auto (the default) and the 12 keys, each shown as a major key and its relative minor. Nothing on the panel shows the choice, not even a label. The choice is kept in the plugin state and in user presets, under `dream-key`. Old projects and presets load on Auto, and factory presets and `--` set Auto. Right-clicking never changes the knob's value, and left-drag and double-click work as before.
- **Dream Eater look:** drawn like the knob in Dropout's Destroy section (The End, in `C:\Users\antho\Dropout`): same size and label style as the other knobs, with a dark grey disc, dark outline and track, a white value arc, a thicker white pointer, and an accent-coloured fill along the white arc showing the live amount. The other knobs keep their look.
- **Gain-reduction meter** in the UI.
- **Loading:** drag-and-drop a WAV, AIFF, or MP3 onto the plugin window, or click inside the waveform rectangle to open the file browser. There is no Load button. With no sample, the rectangle reads exactly "Drop a sample here" and a click anywhere in it opens the browser. With a sample, only a plain click (not a drag, not on the Start or End handle) opens it. The pointer becomes a hand where a click opens the browser. Nothing sits under the title while no sample is loaded; once one is, its name and length show there. MP3s are decoded in pure Rust (Symphonia, `mp3` feature only), with the encoder delay trimmed when the file says how long it is, and stored in the state as decoded audio like any other format. Resample to the host rate.
- **State:** the sample audio itself is embedded in the plugin state, so a Cubase project or preset reopens with the sample even if the original file moved.
- **Presets:** a preset dropdown left of a **Save** button, at the right of the title. **--** (called Init in 1.4) means no sample and default settings, is first in the menu, and is where a new instance starts. It is stored as `{"kind":"none"}`, so projects from any version reopen on it, and neither `--` nor `Init` can be used as a user preset name. The factory presets, in this order after `--`, are **Paper**, **Stone**, **Umber**, **Water**, and **Wind**. Each loads `presets\<Name>.wav`, embedded in the plugin binary with `include_bytes!`, with the default settings, and the sample is named after the preset. Save asks for a name inline (a text field with OK and Cancel, no native dialog) and stores the sample's audio and every parameter value in `%APPDATA%\Haunter\Presets`, one JSON file per preset. Saved presets are listed after the factory ones and persist across sessions. Saving under an existing name overwrites it.
- **Modified indicator:** when any parameter, Start or End, Restart or Reverse, or the sample differs from the selected preset, the name shows a trailing `*` (`Water*`). Choosing the preset again or saving clears it. The selected preset and what it set are saved in the plugin state, so a Cubase project reopens showing the same name and modified state.
- **Latency:** none needed (no lookahead).

## Deliverables
1. Source in this repo, with DSP unit tests (envelope follower, tempo-grid trigger timing, Restart on vs off, Reverse, HP and LP changing the output, start/end, Dream Eater Off being a bypass, Dream Eater changing the output more as it turns up and staying stable at max with peaks at or below 1.02, key detection on synthetic A minor and D major sequences, a smooth retune, the key override kept in the state and presets, state save/restore with the embedded sample, loading old states, decoding a small MP3 fixture, Rate locked with the ∞ readout while Restart is off, the menu order and every factory preset loading its embedded sample, a user preset saved to a temporary folder and read back with its sample and parameters intact, and the `*` appearing after a change and clearing after saving or choosing the preset again).
2. `cargo build --release` produces the DLL. Package it as `release\Haunter.vst3\Contents\x86_64-win\Haunter.vst3` with the proper bundle layout.
3. README with the controls and the install steps.
4. Commit when it builds and the tests pass.
