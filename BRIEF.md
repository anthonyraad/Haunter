# Haunter: build brief

Build a Windows 64-bit **VST3 audio effect** (not an instrument) for Cubase called **Haunter**. The user loads a sample (typically a kick or any one-shot), and the sample's volume shape ducks the incoming track, like a ghost-kick sidechain. The sample can also be blended into the output.

Follow the same Rust approach as `..\Sparkletop\plugin` (look at its Cargo.toml, .cargo config, static CRT, and VST3 bundle layout) and the knob look of the Dropout plugin (`..\Sparkletop` commit 56acf79 copied Dropout's disc, track, and blue arc knobs; reuse that style). Since 1.6.1 the accent is #7C6EBB instead of blue, everywhere: knob arcs, lit toggles, the waveform region, the meter, menu selections, the text cursor, and the Dream Eater fill, with the light and grey tints derived from it. Since 1.7.10 the playhead line on the waveform is pink, #EB789A (RGB 235, 120, 154; it was orange-red #D85A3E).

## Behaviour
- **Trigger:** synced to Cubase's tempo and transport. Rate choices are 1/1, 1/2, 1/4, 1/8, 1/16, plus dotted and triplet variants. Retrigger on the grid only while the transport plays.
- **Sample region:** Start and End times within the sample. Show the waveform in the UI with draggable start and end handles.
- **Restart** toggle, on by default. On: the region plays once from Start on every Rate grid step (from End with Backward; with Levitate, alternately forward from Start and backward from End, since 1.7.7, by the step's parity in the song). Since 1.7.11 a cycle wrap or locate that lands back on a step fires it again even if it just fired (any jump back of more than a quarter step and two frames), so a one-step cycle plays every pass, and a block running across the cycle end (from the host's loop range) is folded back into the cycle so no step past the end fires. Off: the region loops continuously while the transport plays, and the Rate knob keeps its normal look but ignores dragging, scrolling, and double-clicks, with its readout replaced by a grey ∞ (U+221E, from the font if it has the glyph, drawn otherwise). Turning Restart back on shows the fraction again. Old states map One-shot to Restart on and Loop to Restart off.
- **Direction** menu (since 1.7, replacing the Reverse toggle), styled like the preset menu (both centre their text, on the button and in the list, since 1.7.2): **Forward** (the default) plays the region from Start to End; **Backward** plays it from End to Start; **Levitate** ping-pongs between Start and End continuously. Choosing Forward or Backward mid-playback turns the playhead round at once from its current position (within the next block), with a 1 ms crossfade between the old and new directions whose gains add up to one, so there is no click. Levitate turns round at each marker by reflecting: the frame at the marker plays twice and the next ones mirror the last ones, so there is no jump and no fade. With Restart on (since 1.7.7; before, each step restarted it from Start going forward, like Forward), Levitate alternates per Rate step: one step plays forward from Start, the next backward from End, and so on, each retriggered with the same crossfade as Forward and Backward, one pass per step, stopping at the far handle without bouncing. The alternation is set by the parity of the grid step's index counted from the song's start (beat 0 is step 0, forward), taken from the host's song position, so it is the same across loops and wherever playback starts (starting on an odd step starts backward). Restart only triggers with a song position, so no fallback counter is needed. With Restart off it bounces for as long as the transport plays. Switching to Levitate keeps the current direction. When the transport stops, the current pass finishes and stops. The ducking envelope, Dream Eater's swell, the blended sample, and the waveform playhead follow the direction actually playing. It is an automatable enum parameter with the new ID `direction` (the old toggle was `reverse`): old states map Reverse on to Backward and off to Forward, and user preset files and the selected preset saved in a project map the same way (so no false `*`); factory presets set Forward. Old automation of Reverse does not carry over to the new ID. Choosing from the menu holds the edit open (begin, then the value every frame) until the parameter has it or about a second passes, the same as the toggles since 1.2.1, because Cubase does not apply an edit that opens and closes at once; the menu shows the choice meanwhile.
- **Ducking:** an envelope follower runs on the sample's playback (after the HP and LP filters). Its shape sets gain reduction on the input. Controls are Depth (0 to 100%, how much the track ducks at the unfiltered sample's peak), and Attack and Release smoothing for the follower.
- **Filters:** HP and LP cutoffs filter the sample itself, so they change both the sample heard through Sample Blend and the ducking. Filtering away part of the sample makes the duck shallower. They do not filter the track Dream Eater thins.
- **Sample output:** Sample Blend (how much of the sample is mixed into the output, 0 to 100%, default 0, so it's only a ghost).
- **Drive** (ID `drive`, 0 to 100%, default 0, since 1.7.12, replacing Sample Volume `sample-volume`): warm saturation that lifts the body under the peaks. At 0 it is a bit-exact pass-through. Otherwise it saturates the blended sample. It does not saturate Dream Eater. Since 1.7.15 the level is no longer held within 1 dB: the loudness is matched (RMS over 200 ms, measured above 100 Hz through a 12 dB/oct high-pass) and lifted by 3.5 d dB into a soft ceiling under the input's held peak (identity up to a knee of 2/h - 1 with h = 4 d^2 dB, then a C2 tanh shoulder), so the sample's body comes up about 2 to 4 dB at full Drive (about 1 dB at half) with its peaks at or under the clean peak, as the waveform has shown since 1.7.14; a smoothed base-rate guard with a tanh shoulder at 0.99 catches what the half-band filters add to peaks. It also bends the duck envelope with `e + d(tanh(3e)/tanh(3) - e)` so dips are as deep but fuller and longer. The curve is a smooth asymmetric tanh, identity at 0 (gain 2.5 d, bias 0.6 d since 1.7.15; 1.7.14: 3.5 d^2 and 0.3 d; offset and slope normalised), applied to the input normalised by a held peak follower (30 ms hold, 3 s release), with a 4 d dB high-shelf cut at 2.5 kHz (9 d dB before 1.7.15) before it and its inverse after, a one-pole low-pass closing from 40 to 12 kHz with drive, 4x oversampling through two polyphase IIR half-band stages (100 and 110 dB), a 20 Hz DC blocker on only what the curve and ceiling change (so the input's lows pass untouched and the bias builds up no sub), and a 10 ms engage fade. No hard clipping anywhere. About 5 frames of latency while engaged, not reported. Old states and presets fold Sample Volume into Blend (`blend = min(1, blend * volume)`) and add Drive at 0; Sample Volume automation is lost.
- **Drive on the waveform** (since 1.7.13): the waveform columns go through the same shared curve as the audio (`drive::Transfer`, via `drive::driven_columns`): normalised to their peak, bent, less the offset the DC blocker takes out of a tone with the column's swing (since 1.7.15), and peak-matched back so the loudest point stays at the clean waveform's height (since 1.7.14; 1.7.13 RMS-matched, which shrank the peaks), at the clean waveform's scale. Since 1.7.15 the audio matches it: the body comes up under the peaks. The shown Drive glides toward the knob's (60 ms time constant, landing on it exactly), the bent columns are cached and recomputed only for a new sample, a move of more than 0.002, or on landing, and the waveform colours lerp toward #BFBFEC (since 1.7.14; the playhead colour in 1.7.13) by 15% times Drive. Drive 0 draws exactly as 1.7.12; playhead, handles, and shading unchanged.
- **Mix:** dry/wet for the ducking effect. There is no output gain: the output is always at unity. Old states that saved Output still load, and the value is ignored.
- **Dream Eater** (since 1.7.16): a spectral gate on the incoming track. It thins that track until the strongest partials remain, then the sample envelope ducks it the same way as with the knob off. It adds nothing and does not listen for a key. Since 1.7.18 the partials bloom and fade instead of chirping, and the gate runs only while a sample is loaded.
  - **The gate:** one Hann short-time transform of about 40 ms (2048 samples at 44.1 and 48 kHz), hopping by an eighth of that, with the Hann window again on the way out so a moving gain crossfades. Left and right are transformed separately and share one decision, so a partial loud on either side stays on both. The threshold sits under the frame's loudest bin: about -60 dB at 30%, -30 dB at 60%, and -12 dB at 100%. Bins 3 dB above it stay open. Below that they ease to a floor across 28 dB. The floor is about -22 dB at the bottom of the knob, -31 dB at 30%, -43 dB at 60%, and -64 dB at full. Bin levels are smoothed and blurred across their neighbours, and each gain blooms over about 20 ms and fades over about 180 ms, in decibels. The knob eases in over the first 5% and is smoothed over 20 ms.
  - **Where it sits:** on the incoming track, before the duck. The sample envelope is applied to the thinned track afterwards, delayed by the same frame so the dips stay sharp. The blended sample is delayed with it and is not thinned or ducked. HP, LP, and Drive still act on the sample and the duck only.
  - **Off and latency:** fully counter-clockwise is Off, a bit-exact, zero-latency bypass, and the readout says "Off". Above Off, with a sample loaded, the output is delayed by one frame and that latency is reported to the host. Turning it off is bit-exact again once the gate has settled. With no sample loaded it is bit-exact at every knob position, the transform is skipped, and the knob is dimmed. Silence in is silence out.
  - **The saved key:** projects and presets still store `dream-key`, so older sessions load, and the gate ignores it. Factory presets and `--` still store Auto.

- **Dream Eater look:** drawn like the knob in Dropout's Destroy section (The End, in `C:\Users\antho\Dropout`): same size and label style as the other knobs, with a dark grey disc, dark outline and track, a white value arc, a thicker white pointer, and an accent-coloured fill along the white arc showing the live amount. The other knobs keep their look.
- **Gain-reduction meter** in the UI.
- **Loading:** drag-and-drop a WAV, AIFF, or MP3 onto the plugin window, or click inside the waveform rectangle to open the file browser. There is no Load button. With no sample, the rectangle reads exactly "Drop a sample here" and a click anywhere in it opens the browser. With a sample, only a plain click (not a drag, not on the Start or End handle) opens it. The pointer becomes a hand where a click opens the browser. Nothing sits under the title while no sample is loaded; once one is, its name and length show there. MP3s are decoded in pure Rust (Symphonia, `mp3` feature only), with the encoder delay trimmed when the file says how long it is, and stored in the state as decoded audio like any other format. Resample to the host rate.
- **State:** the sample audio itself is embedded in the plugin state, so a Cubase project or preset reopens with the sample even if the original file moved.
- **Presets:** a preset dropdown left of a **Save** button, at the right of the title. **--** (called Init in 1.4) means no sample and default settings, is first in the menu, and is where a new instance starts. It is stored as `{"kind":"none"}`, so projects from any version reopen on it, and neither `--` nor `Init` can be used as a user preset name. The factory presets, in this order after `--`, are **Daisy**, **Paper**, **Press**, **Spin**, **Stone**, **Umber**, **Water**, and **Wind**. Each loads `presets\<Name>.wav`, embedded in the plugin binary with `include_bytes!`, with the default settings, and the sample is named after the preset. Daisy replaced Gaze in 1.7.6; a project saved on Gaze must still reopen with its sample (kept in the state) and show Gaze, without panicking, though Gaze is no longer in the menu and its name is free for user presets. Save asks for a name inline (a text field with OK and Cancel, no native dialog) and stores the sample's audio and every parameter value in `%APPDATA%\Haunter\Presets`, one JSON file per preset. Saved presets are listed after the factory ones and persist across sessions. Saving under an existing name overwrites it.
- **Modified indicator:** when any parameter, Start or End, Restart or Direction, or the sample differs from the selected preset, the name shows a trailing `*` (`Water*`). Choosing the preset again or saving clears it. The selected preset and what it set are saved in the plugin state, so a Cubase project reopens showing the same name and modified state.
- **Latency:** none needed (no lookahead).
